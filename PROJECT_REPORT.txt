1. GLOBAL IDEA
================================================================================

1.1 VISION
---------
One single web platform where the whole robotics club — from the Supervisor down
to simple Guests — manages its departments, communicates and organizes events.

  Supervisor -> Leader -> Co-Leader -> Managers -> Members -> Guests

It replaces the current reality of scattered WhatsApp groups, Excel files and
loose folders.

1.2 PAIN POINTS ADDRESSED
-------------------------
  * Scattered communication (WhatsApp noise, no structure)
  * No central member registry
  * Manual, chaotic event organisation
  * Untracked materials and equipment
  * Invisible finances (sponsorships, budget, expenses)
  * No possibility of remote collaboration

1.3 SOLUTION (MVP)
------------------
  * Authentication + 6 roles with strict, server-side permissions
  * 4 active departments (HR, Events, Media, Finance) + Materials "Coming soon"
  * Every department has a PUBLIC HOME PAGE (announcements, votes, comments,
    sponsor offers, clips, albums) and a PRIVATE SPACE (chat + tasks)
  * Chat: global / managers / department / 1-to-1 private, with file & image
    attachments, live via Socket.io
  * Votes (Yes/No, 1 per user, changeable, transparent) + comments
  * Members directory (hidden from guests) -> click a member = open private chat
  * Albums browsable by all members, managed by the Media department
  * HR: manual attendance, meeting conclusions, rule-break alerts
  * Events: itinerary/journey + decoration planning
  * Global calendar (Leader writes, everyone reads) + goals per department
  * Supervisor dashboard with real aggregated graphs
  * Supervisor reports: monthly / full year / per department (PDF, pdfkit)
  * In-app notifications
  * Off-site backups: local + monthly Google Drive snapshots, Storage page
    with quota alerts

1.4 TRUST CHAIN (multi-club, no free role escalation)
-----------------------------------------------------
  * One install hosts MANY clubs; every row of club data is scoped by club_id.
  * First page = Sign in / Create a club. POST /api/auth/create-club (public
    /signup) creates a club + its five departments and makes the founder its
    FIRST SUPERVISOR. It grants no power over any other club. (Replaces the
    earlier one-time /signup bootstrap; see the changelog below.)
  * Inside a club, accounts are made on the chain:
      - Supervisor -> "Create account" (Members page): role Leader, or
        another Supervisor (a club may have several)
      - Leader / Co-Leader -> create every other account
      (Co-Leader, Manager, Member, Guest) AND whole departments
      (POST /api/departments, optionally with the first manager/members)
  * Manager / Member / Guest -> 403, no self-registration endpoint exists
  * Self-service profile: every signed-in user edits their OWN name/bio and
    password (PATCH /api/users/me, POST /api/users/me/password). Role and
    department are NEVER self-editable.

2. ROLES, DEPARTMENTS & FEATURES
================================================================================

2.1 ROLES
---------
  Role          Powers
  ------------  ----------------------------------------------------------
  Supervisor     Sees everything (graphs, goals, all tasks, all chats).
                READ-ONLY on management (no posts/comments/member edits/
                tasks/calendar/department tools) — with TWO writes: creating
                Leader accounts AND adding further Supervisors. Chats like a
                member. CAN vote. Downloads reports (monthly / yearly / dept).
  Leader        Full control: departments, chats, assigns goals, owns the
                global calendar, promotes/removes users, creates accounts,
                creates whole departments (+ their first manager/members).
  Co-Leader     Same powers as Leader, including accounts and departments.
  Manager       Own department (HR / Events / Media / Finance): public home
                content, private space, tasks, department chat.
  Member        Belongs to 1 department: tasks, chats, votes, directory.
  Guest         Public home pages ONLY: no directory, no votes, no chats.

  "Bosses" = Supervisor + Leader + Co-Leader -> access everything.

2.2 DEPARTMENTS
---------------
  HR       Public: announcements | Private: meeting conclusions, manual
           attendance, rule-break alerts, tasks
  Events   Public: announcements | Private: itinerary, decoration planning,
           tasks
  Media    Public: clips with 👍/👎 vote + comments + album cards | Private:
           album/photo management, tasks
  Finance  Public: sponsor offers (money OR goods) with vote + comments |
           Private: sponsor pipeline, budget/expenses, tasks
  Materials  ⏳ Coming soon (deferred to PROD)

2.3 CHAT ROOMS
--------------
  💬 Global      : everyone including the Supervisor
  👔 Managers    : 4 managers + leader + co-leader + supervisor
  🏢 Department  : department members + leaders + supervisor
  🔒 Private 1↔1 : opened by clicking a member of the directory
  Bosses see all rooms. Attachments are private + HMAC-signed URLs.

5. NETWORK ARCHITECTURE
================================================================================

The project has ONE code base and THREE possible deployment modes. All three
expose the same URL space: /api/*, /socket.io/*, /uploads/*, everything else
= SPA.

---------------------------------------------------------------------------
MODE A — VERCEL (recommended, online, current target)
---------------------------------------------------------------------------

   Members (anywhere, any network, phone or PC)
        |  HTTPS
        v
   +--------------------------------------------------+
   |  VERCEL EDGE / ROUTER   (vercel.json: builds +   |
   |  routes, legacy model; installCommand installs   |
   |  platform/server + platform/client deps)         |
   |   /socket.io/*  -> platform/server/index.js      |
   |   /api/*        -> platform/server/index.js      |
   |   /uploads/*    -> platform/server/index.js      |
   |   /assets/*     -> platform/client/assets/$1     |
   |   /favicon.ico  -> platform/client/favicon.ico   |
   |   /favicon.svg  -> platform/client/favicon.svg   |
   |   /icons.svg    -> platform/client/icons.svg     |
   |   /*            -> platform/client/index.html    |  (SPA fallback)
   +--------------------------------------------------+
        |                          |
        | serverless function      | static files
        v                          v
   +---------------------+   +------------------------+
   | Express 5 + Socket  |   | React build (client/   |
   | @vercel/node        |   | dist) served from      |
   | (maxDuration via    |   | /platform/client/      |
   |  dashboard if slow) |   +------------------------+
   +--+-------+-------+--+
      |       |       |
      |       |       +--> Vercel Blob  (BLOB_READ_WRITE_TOKEN)  uploads
      |       +----------> Upstash Redis (REDIS_URL)  Socket.io
      |                                              pub/sub adapter ->
      |                                              live chat across
      |                                              function instances
      +------------------> Turso (TURSO_URL + TURSO_AUTH_TOKEN)
                                              hosted SQLite (libsql HTTP)

   +------------------ cron ------------------------------+
   |  GET /api/storage/cron-sync                          |
   |  schedule "0 3 * * *" (daily on Hobby plan)          |
   |  guarded by CRON_SECRET, skips every day except      |
   |  "this month is not backed up yet" -> once a month   |
   +----------------------|-------------------------------+
                          v
                Google Drive  ISIGK-Club-Backups/YYYY-MM
                (driveClient.js — service account or OAuth refresh token)

   Characteristics
     - Single Vercel project = API function + static client (one origin,
       no CORS/cookie issues)
     - Hobby plan limits accepted: WebSocket capped at 300 s (engine.io
       auto-reconnects, every handler is reconnect-safe), request body
       ~4.5 MB (client re-encodes large images), daily crons only
     - Traffic encrypted end-to-end by Vercel HTTPS
     - Env vars: JWT_SECRET (REQUIRED), ISIGK_DEMO_ACCOUNTS=0, CRON_SECRET,
       TURSO_URL/TURSO_AUTH_TOKEN, BLOB_READ_WRITE_TOKEN, REDIS_URL,
       CORS_ORIGIN (optional), ISIGK_DRIVE_* credentials

---------------------------------------------------------------------------
MODE B — SELF-HOST (own machine or school server, public or LAN)
---------------------------------------------------------------------------

   git clone https://github.com/med-tlili/robotic_club.git
   cd robotic_club/platform/server && npm install && npm start

   Client (built, committed in client/dist) and API served by the SAME
   Express process on ONE port (PORT, default 4000):

        browser  --HTTP:4000-->  Express
                                   |-- static  platform/client/dist
                                   |-- /api/*  routes
                                   |-- /uploads (local disk, signed URLs)
                                   |-- /socket.io (in-memory adapter)
                                   +-- club.db on local disk

   Backups: local `npm run backup` + rclone -> gdrive:ISIGK-Club-Backups
   (rclone configured once with a browser consent).

---------------------------------------------------------------------------
MODE C — "YOUR PC IS THE SERVER" (LAN / WiFi, START-SERVER.bat)
---------------------------------------------------------------------------

   [Supervisor's laptop]                         [Members on the same WiFi]
   +---------------------------------+          +-------------------------+
   | START-SERVER.bat                |          | PC / phone browser      |
   |  -> cd platform\server          |          |                         |
   |  -> npm install (first run)     |  WiFi    | opens http://192.168.x.x|
   |  -> npm start (start-prod.js)   | <------> | :4000                   |
   |                                 |  router  +-------------------------+
   | Node.js listens on 0.0.0.0:4000|
   | Windows Firewall: inbound TCP   |
   |  4000 ALLOW ("ISIGK Club -      |
   |  port 4000", profile Any)       |
   +---------------------------------+

   Setup (once, as Administrator):
     New-NetFirewallRule -DisplayName "ISIGK Club - port 4000" `
       -Direction Inbound -Protocol TCP -LocalPort 4000 `
       -Action Allow -Profile Any

   Startup banner prints every LAN address: "📡 Club members open: http://…:4000"
   (verified: http://192.168.1.11:4000 -> HTTP 200 on the Wi-Fi adapter;
    192.168.56.1 in the log is the VirtualBox adapter — members use 192.168.1.x)

   Rules / limits of this mode
     - The laptop must stay ON with the server window open
     - The router's DHCP address can change -> RESERVE the address in the
       router's DHCP settings so the club link never breaks
     - Same-network only; members on mobile data / other WiFi cannot reach it
       -> optional tunnels offered but not built:
          · Tailscale : free fixed private address per member
          · Cloudflare Tunnel : public link

DATA FLOWS
---------------------------------------------------------------------------
   Authentication : POST /api/auth/login -> JWT (Bearer) -> stored client-side
                    -> sent on every fetch + as Socket.io `auth.token`
   REST calls     : /api/** (JSON) — one JSON error handler, API failures
                    never return HTML
   Real-time      : Socket.io rooms
                      room:<key>       department / global / managers rooms
                      user:<uid>       per-user activity
                      dm:<a>-<b>       private thread
                    events: chat:message, chat:activity, notification pushes
   Uploads        : client re-encode (>3.5 MB) -> POST multipart -> multer
                    engine -> random name -> sharp thumb ->
                    public: redirect to store / private: proxy after
                    HMAC signature check (?e=<unix>&s=<sig>)
   Backups        : club.db (VACUUM INTO or JSON export) + uploads/ tree ->
                    rclone (local) or Drive REST (Vercel) -> YYYY-MM folder,
                    bookkeeping in drive_backups + settings kv

8. HTTP API OVERVIEW
================================================================================

  Mounted in index.js (all under /api):

    /api/auth          POST login (rate-limited) · POST create-club
                       (new club + its first Supervisor; rate-limited) ·
                       GET me
    /api/users         GET directory (not guest) · POST create account (chain)
                       PATCH /me + POST /me/password (self-service profile)
    /api/departments   GET list (your club) · POST create a department
                       (Leader/Co-Leader) with optional manager + members ·
                       PATCH :slug rename/re-describe (slug stays) ·
                       GET :slug/usage (what a delete affects) ·
                       DELETE :slug (people -> 409; content needs ?confirm=1) ·
                       GET :slug (your club; member list decided server-side
                       by role) · GET :slug/private (dept members + bosses)
    /api/goals         GET · POST (Leader/Co-Leader)
    /api/posts         GET ?department_id= (one dept) · GET /feed (the CLUB
                       home feed: all depts, club-scoped, cursor-paginated)
                       POST create: type text|image|video|poll (media must
                       match the type; poll 2-6 options)
                       + POST /:id/vote (reaction yes|no|maybe, not guest)
                       + POST /:id/poll-vote (one option per member)
                       + comments (canWrite: not guest, not supervisor)
    /api/events        calendar (auth required; every member incl. guests
                       reads, Leader/Co-Leader writes)
    /api/applications  club applications
    /api/tasks         department tasks
    /api/notifications list / mark read
    /api/chat          rooms: global · managers · dept:<id> · dm
                       (canSend == canRead; supervisor can write everywhere;
                        guests 403 on everything)
    /api/meetings      live rooms (scope global|department|private).
                       POST = LEADERSHIP only (supervisor/leader/coleader/
                       manager). /:id/join = ask (pending until the HOST
                       accepts via /:id/requests/:userId); /:id/respond =
                       an INVITED person answers their own invite (a
                       requester cannot self-accept). /:id/messages = the
                       meeting chat, accepted participants only. /end closes
                       posting, keeps the transcript. Club-scoped; a foreign
                       or invisible meeting answers 404.
    /api/reports       monthly global / full-year / per-department PDF
    /api/media         DEPARTMENT photo albums (phase 6). ?department_id=
                       selects the department (omitted -> Media, legacy).
                       GET = any member (guests 403); create/upload/delete/
                       share = that department's manager or a club leader
                       (canManageDept). Upload -> thumbs, share-to-feed
                       COPIES the file into that department's feed post.
                       DELETE /albums/:id unlinks an album's files.
    /api/hr            attendance, meeting notes, alerts
    /api/plans         itinerary, decoration
    /api/finance       sponsors (money needs value, goods needs details),
                       budget entries
    /api/storage       Drive sync/re-sync/clear, quota, alerts,
                       GET /api/storage/cron-sync (guarded by CRON_SECRET)

9. SECURITY MODEL
================================================================================

  * Auth           JWT Bearer (jsonwebtoken) + bcryptjs cost 10
  * Secret         FAIL-CLOSED: env JWT_SECRET -> .jwt-secret file ->
                   generated once (local dev only). On Vercel/production with
                   nothing configured it becomes NULL and every auth route
                   answers 503 — no fallback to a public, forgeable default
  * Rate limiting  in-memory fixed-window (15 min) on login (10/IP+email,
                   40/IP) and signup-supervisor (5/IP); reads x-forwarded-for
                   behind Vercel (best-effort per instance)
  * Authorisation  enforced SERVER-SIDE on every route (role + department),
                   mirrored client-side only for UX; role/department are
                   re-read from the DB on every request (nothing trusted from
                   the token beyond the user id)
  * Guests         blocked from directory, albums, chats, votes; but CAN read
                   the club calendar (a club member like anyone else)
  * Supervisor      read-only on management; his writes are creating Leader
                   accounts and adding further Supervisors; CAN chat and vote
  * Account chain  Manager/Member/Guest cannot be self-registered (403);
                   no endpoint mints leader/manager from the public side
  * Profile        self-edit own name/bio/password only; role + department
                   stay on the Leader-only endpoints (no privilege escalation)
  * Private files  uploads/private never served statically — 24h HMAC-signed
                   URLs (?e=<unix>&s=<sig>), timingSafeEqual, proxied so the
                   storage URL never leaks to the browser
  * Uploads        multer validates an EXTENSION ALLOWLIST + random on-disk
                   names; path traversal blocked
  * Filenames      random on disk (timestamp-hex8.ext); original names kept
                   in DB for display only
  * Orphans        deletes unlink files; album delete removes photo + thumb;
                   share-to-feed copies the file so two owners never share
                   one physical file
  * CORS           explicit allowlist (CORS_ORIGIN, comma-separated) +
                   localhost in dev only — corsCheck uses the (origin,
                   callback) signature so no blanket "*" is ever emitted
  * Headers        X-Content-Type-Options nosniff · X-Frame-Options SAMEORIGIN
                   · Referrer-Policy strict-origin-when-cross-origin
  * Errors         dedicated JSON error handler (no HTML from the API)
  * Cron           guarded by CRON_SECRET (404 when unset/mismatched)
  * Git hygiene    DB, uploads, backups, node_modules, .jwt-secret ignored

    2. Marketplace: Turso + Vercel Blob (+ Upstash only for multi-instance)
    3. Env: JWT_SECRET (REQUIRED — auth 503s without it),
            ISIGK_DEMO_ACCOUNTS=0, CRON_SECRET, optional CORS_ORIGIN,

    4. Deploy -> open /signup -> create the club (you become its Supervisor)
            -> Leader -> the rest. Anyone else can create their own club too.

    Socket.io never attaches; chat history works over HTTP but new text
